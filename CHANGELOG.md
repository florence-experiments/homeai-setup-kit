# Changelog

## 2026-11-17

- **Optional OpenRouter cloud models.** HomeAI can list cloud models in the model picker next to the local llama.cpp ones. To turn this on, copy `payload/homeai/cloud.example.json` to HomeAI's `data\cloud.json` and put your OpenRouter API key (on its own line) in `data\openrouter.key`, or set `OPENROUTER_API_KEY`. Then press **Rescan**. The examples are DeepSeek V4 Pro, GLM 5.3 and Kimi K3.1 Pro, plus Hermes 4 405B, which is listed but switched off. Cloud models show as **Cloud** and have no Load or Eject button. They are only used when you pick one by hand, never by Auto routing or the classifier. Only those requests leave the PC, sent over HTTPS by HomeAI's own Python process with the fixed safety rule still applied. The key is never logged or sent to the browser. Fields that only llama.cpp understands are removed, and the Think / No think toggle maps to OpenRouter's `reasoning` setting. If the key is missing, the chat shows a clear error. Without `cloud.json`, nothing changes.
- **HomeAI web access: links you paste are now read.** With the Web toggle on, up to 3 links in your message are opened and read (up to 12,000 characters each) and placed first in the sources. The search query no longer includes the raw URLs.
- **JavaScript pages.** When a page's plain download has almost no text (for example Google Sites or many shops), HomeAI retries it in headless Chromium through Playwright. This is optional: install it with `py -3 -m pip install playwright` and `py -3 -m playwright install chromium-headless-shell`. Without it, HomeAI falls back to the plain text as before. The rendered page may only load public http(s) addresses, and images, media and fonts are skipped.
- **Welcome screen** shows all helpers as smaller cards, not just the first 3.
- **Smarter web search when you paste a link.** HomeAI reads the linked page first and searches on its topic (the page title, any boards or platforms it mentions, plus `github`) instead of the sentence around the link, which used to pull in unrelated results. A GitHub link searches on its owner and repo name. Messages without a link search as before.
- **Welcome screen layout.** The content starts near the top, the prompt box sits just under it (it returns to the bottom once a chat starts), and the box is taller. The example prompts are replaced by links to the GitHub projects HomeAI is built on: llama.cpp releases, ComfyUI, SearXNG, Playwright, faster-whisper and Kokoro.
- **Model picker scrolls** when the list is taller than the window.

## 2026-11-10

- **OpenHands** now uses the official Agent Canvas image `ghcr.io/openhands/agent-canvas:1.38.0` (was 1.33.0). Re-run setup, or pull the new image and recreate the container, to switch an existing install.
- **Stop a running OpenHands task** without stopping the container or the AI engine: `python openhands_ctl.py stop-task`, or the new `Stop-OpenHands-Task.ps1` / `stop-openhands-task.sh` helpers in `extras/openhands`. These call the OpenHands interrupt API.
- **Stop OpenHands task** now also ends leftover processes the agent started inside the container (children of the agent's tmux/terminal sessions, plus detached leftovers). PID 1, the Agent Canvas servers, and other processes needed to keep serving :3000 are left running.
- **16,384-token reply cap.** New installs write `n-predict = 16384` in the `[*]` section of `engine/models.ini`. A client's `max_tokens` still overrides this. OpenHands `max_output_tokens` now uses `min(16384, max(1024, ctx // 2))`, so a 32k-context model can use the full 16,384-token cap (it was previously limited to `ctx // 4`). Existing `models.ini` files are not rewritten until you add a mode or re-run setup; you can add the `n-predict` line yourself.
- **llama.cpp:** setup still installs the newest matching official build when you update the engine. A newer build is not always faster. In testing, b12244 was slower than b11840 on Vulkan (prompt about 485–617 vs 1138 tokens/s, generation 62–64 vs 73 tokens/s, and about 0.75 GB more shared memory). If a new build feels slower, keep the known-good copy; setup only replaces the engine when you run it again.
- HomeAI's model picker already unloads a loaded model with `POST /models/unload` and leaves the llama-server router running. There is no separate "Release AI Models" script in this kit.
